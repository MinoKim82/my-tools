# 운영 지침 및 결정 기록 (Operational Learnings & ADR)

이 문서는 `my-tools` 모노레포의 아키텍처 결정(ADR, Architecture Decision Record) 및 개발 운영 과정에서 도출된 핵심 정책과 노하우를 누적 관리하는 기록서입니다.

새로운 도구를 개발하거나 기존 체계를 개편하면서 도출된 중요한 아키텍처 결정은 본 문서에 순차적으로 기록하여 팀과 AI 에이전트가 언제든 설계 배경(Rationale)을 파악할 수 있도록 합니다.

---

## 아키텍처 결정 기록 (Architecture Decision Records)

### [ADR-1] `./tools/<tool-name>` 전용 컨테이너 폴더 구조 채택 (2026-09-13)
- **맥락 (Context)**: 도구가 지속적으로 늘어남에 따라 루트 디렉토리가 난잡해지고, 프로젝트 전역 설정과 개별 도구 영역 간의 충돌 위험이 존재함.
- **결정 (Decision)**: 모든 개별 도구는 `./tools/<tool-name>/` 디렉토리 하위에만 배치하여 루트 디렉토리의 청결성과 탐색 효율을 보장함.

### [ADR-2] 완전 독립 자립 원칙 (Zero-Coupling Policy) 확정 (2026-09-13)
- **맥락 (Context)**: 도구 간에 공통 라이브러리를 공유할 경우, 한 도구의 라이브러리 버전 업데이트가 다른 도구의 동작을 깨뜨릴 수 있음.
- **결정 (Decision)**: 도구 간 의존성 간섭을 원천 차단하고 단독 복사 및 실행이 가능하도록 각 도구는 다른 도구를 참조하지 않는 완전 독립 자립형(Stand-alone) 구조를 유지함.

### [ADR-3] 표준 툴체인 선정 (Python `uv`, TS `pnpm`) (2026-09-13)
- **맥락 (Context)**: 다국어(Polyglot) 도구 작성을 허용하되, 에이전트나 개발자마다 다른 패키지 관리자(pip, poetry, npm, yarn 등)를 임의로 혼용하면 유지보수가 어려워짐.
- **결정 (Decision)**: Python은 초고속 격리 툴체인인 `uv`(`uv run`, `uv add`), TypeScript/Node는 `pnpm`(또는 `bun`)을 공식 표준 툴체인으로 지정함.

### [ADR-4] 도구별 격리된 `src/.env` 및 `src/.env.example` 필수화 (2026-09-13)
- **맥락 (Context)**: 외부 API 키(OpenAI, Anthropic 등) 및 시크릿이 중앙에서 공유되거나 Git에 유출될 위험 방지.
- **결정 (Decision)**: 모든 설정과 시크릿은 각 도구의 `src/.env`에서만 관리하고 `.gitignore`로 커밋을 차단하며, 신규 도구 생성 시 더미 키가 포함된 `src/.env.example`을 필수로 동봉함.

### [ADR-5] 루트 카탈로그 및 문서 자가 갱신(Living Document) 지침 도입 (2026-09-13)
- **맥락 (Context)**: 도구가 계속 늘어나면 어떤 도구가 있는지 한눈에 파악하기 어렵고 문서가 실제 코드와 괴리됨.
- **결정 (Decision)**: 신규 도구 추가 또는 변경 시 루트 [README.md](../README.md)의 **Tools Catalog 표**를 즉시 최신화하고, 대화 중 도출된 새로운 규칙은 [AGENTS.md](../AGENTS.md) 및 본 문서에 능동적으로 기록함.

### [ADR-6] 스코프 기반 Conventional Commits 채택 (2026-09-13)
- **맥락 (Context)**: 다수의 독립 도구가 공존하는 모노레포에서 커밋 로그만 보고 변경 대상을 파악하기 어려움.
- **결정 (Decision)**: `<type>(<tool-name>): <description>` 커밋 형식을 채택하여 변경된 도구의 이름을 커밋 스코프로 강제함.

### [ADR-7] 에이전트 연동용 SKILL.md 필수 동봉 및 /skill-creator 표준화 (2026-09-13)
- **맥락 (Context)**: 도구가 CLI 터미널 실행에만 머무르면 AI 에이전트가 이를 자율적으로 인지하고 작업에 활용하기 어려움.
- **결정 (Decision)**: 모든 도구에 에이전트 스킬 명세서(`SKILL.md`)를 필수로 동봉하며, 에이전트의 언더트리거링 방지와 고품질 스킬 명세를 위해 반드시 `/skill-creator` 스킬 지침을 준수하여 작성함.

### [ADR-8] 도구 내부의 skill/ 및 src/ 이원화 서브폴더 구조 채택 (2026-09-13)
- **맥락 (Context)**: 도구 폴더 내에 모든 소스코드가 혼재될 경우, 에이전트 스킬 경로 심링크 시 `.venv/`, `node_modules/`, 테스트 파일 등의 노이즈가 스킬 컨텍스트에 유입되어 토큰 낭비와 인덱싱 저하를 유발함.
- **결정 (Decision)**: `tools/<tool-name>/` 아래에 `skill/`(에이전트 스킬 명세)과 `src/`(실제 코드, 의존성, 테스트)를 완전히 분리하여 관심사를 격리하고, `make link`와 `make link-skill`을 통한 듀얼 인터페이스를 확립함.

### [ADR-9] 운영 지침 및 결정 기록의 docs/ 분리 및 모듈화 (2026-09-13)
- **맥락 (Context)**: 아키텍처 결정(ADR)이 누적될수록 `AGENTS.md`의 길이가 길어져 AI 에이전트가 매 세션마다 읽어야 하는 초기 컨텍스트(토큰) 비용이 증가하고 핵심 가이드라인의 집중도가 분산됨.
- **결정 (Decision)**: 누적되는 ADR 및 상세 결정 기록은 `docs/decisions.md`로 분리하여 별도 관리하고, `AGENTS.md`에는 핵심 원칙과 참조 링크만 유지함.

### [ADR-10] 저장소 내 문서 참조 시 순수 상대 경로 강제 (Portable Relative Links Policy) (2026-09-13)
- **맥락 (Context)**: 로컬 머신의 절대 경로(`file:///Users/...`)를 문서 링크에 사용할 경우, 다른 PC나 환경에서 git clone 시 링크가 전부 깨져 문서 이식성이 훼손됨.
- **결정 (Decision)**: 저장소 내의 모든 Markdown 문서 간 참조는 반드시 Git 저장소 기준의 순수 상대 경로(`README.md`, `../README.md`, `docs/decisions.md` 등)를 사용하며, 로컬 머신 절대 경로를 파일 내에 영구 커밋하지 않도록 강제함.

### [ADR-11] 커밋 타이밍 및 사전 체크리스트(Pre-Commit Checklist) 수립 (2026-09-13)
- **맥락 (Context)**: 언제 커밋해야 하는지에 대한 명확한 기준이 없으면 작업 단위가 너무 커지거나 깨진 코드가 중간에 커밋되어 히스토리 추적이 어려워짐.
- **결정 (Decision)**: 신규 도구 완료, 기능 추가/버그 수정 및 테스트 통과, 문서 정책 개편 등 '논리적 마일스톤 완료 즉시' 원자적(Atomic)으로 커밋하는 규칙을 확립하고, 커밋 전 테스트 통과, `.env` 누출 방지, 카탈로그 동기화, 상대 경로 확인의 4대 체크리스트를 의무화함.
